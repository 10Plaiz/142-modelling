# Verify the parking notebook

The notebook is the user-facing study. Read [the feature map](features/README.md)
before execution. The normal-demand CLI is a separate, smaller entry point and
does not prove the full notebook works.

## Launch

From the repository root, prepare the Python 3.12 project environment:

```bash
uv sync --locked
uv run --locked python Group8_Parking_Booth_Simulation/tools/verify_notebook.py --doctor
```

Readiness is `DOCTOR PASS`, identifying this repository's .venv Python and valid
notebook and input files. There is no server to keep running. The execution
helper launches a fresh kernel and owns its teardown.

## Doctor

The `--doctor` command above is read-only. It checks the Python version, project
environment, notebook format, input values, and all 48 ordered arrival slots.
Run it first when anything looks wrong. A failure is not a reason to substitute
global Python or generate missing campus data. Correct the actual dependency or
input problem and repeat the check.

## Drive

```bash
uv run --locked python Group8_Parking_Booth_Simulation/tools/verify_notebook.py
```

This performs fresh-kernel Run All on the real notebook, with cleared prior
outputs and the model, rendering helper, and two campus input CSVs copied to
isolated scratch space. It executes all checks and all nine combinations.
It recalculates the exported means, standard deviations, and intervals from raw
replications. It checks precision, seeds, morning results, activity-time
sensitivity, figures, and unchanged inputs.

Require exit code zero, `Status: passed; scratch removed`, and a passing manifest.
Do not treat old notebook output or a successful doctor as execution proof.

When the user asks to refresh working results, the same command may use
`--publish`. It archives previous generated exports under
`Group8_Parking_Booth_Simulation/archive/pre-presentation/` and copies the checked
notebook and exports into place. Do not run two publishers concurrently.

## Evidence

Each run prints its unique evidence directory under
`artifacts/notebook-verification/`. Retain:

- `execution.log`, which records the action, Python, executed cells, output, and errors.
- `manifest.json`, with status, input and source hashes, counts, elapsed time,
  output hashes, and scratch-cleanup status.
- The executed notebook and `notebook.html`, including actions and their outputs.
- `results/` and `figures/` generated by that exact run.

Exercise the real notebook path and inspect resulting exports, not internal
setters or saved historical results. Do not mock the simulation. This workflow
does not require public-data downloads or send external messages.

Require all code cells executed, every recorded model check passing, nine
complete main combinations with at least 30 days each, and nine activity-time
cases at normal arrival demand. The normal timing cases reuse the main baseline.
Require valid intervals, stated precision, consistent units, and unchanged inputs.
Read the interpretation alongside the morning results and sensitivity tables.
Verification does not establish field validation or instructor approval of the
revised model. See the feature recipes for interpretation checks.

## Cleanup

The notebook client shuts down its own kernel, including after execution errors.
The helper removes its temporary working directory on both success and failure.
It preserves evidence and any partial outputs. After a run, confirm that
`manifest.json`, `execution.log`, and the executed notebook still exist at the
printed location. Never kill by process name or remove the evidence directory.

Independent verification runs have separate scratch and evidence directories.
Wait for a running command to finish before starting a replacement for it.

## Helpers

The executable helper is
`Group8_Parking_Booth_Simulation/tools/verify_notebook.py`. Its `--doctor`, normal,
and `--publish` invocations are documented above. It reuses the notebook's model
checks instead of implementing another simulation.

Keep the feature map aligned with the notebook using `/maintain-verification-skill`.
